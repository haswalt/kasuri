# Kasuri web app

The browser interface for Kasuri: the workflow editor and canvas, run history and inspector, simulation controls, data tables and workspace settings. It is a React single-page application built with Vite and styled with [Panda CSS](https://panda-css.com).

The app holds no workflow logic of its own. Validation, execution, simulation and persistence all happen in the Rust Worker, which the app calls over `/api`. In production the Worker serves the built app from `apps/web/dist` as static assets.

For the project as a whole, start with the [main README](../../README.md).

## Development

Run commands from the repository root.

```sh
pnpm install
pnpm dev
```

`pnpm dev` builds the Worker and this app, then serves both with Wrangler at `http://127.0.0.1:8787`.

For frontend work with hot reload, keep `pnpm dev` running and start the Vite dev server in a second terminal:

```sh
pnpm dev:web
```

Vite proxies `/api` to the Worker on port 8787, so the app talks to a real backend. There is no mock or demo data.

| Command | What it does |
| --- | --- |
| `pnpm dev:web` | Start the Vite dev server |
| `pnpm build:web` | Generate Panda styles, type-check and build into `dist/` |
| `pnpm test:web` | Run the unit tests in `tests/` |
| `pnpm --filter web lint` | Lint with Oxlint |

## Layout

| Path | Contents |
| --- | --- |
| `src/App.tsx` | Application shell, routing and top-level views |
| `src/components/` | Editor, canvas, inspector builders, run details, data tables, MCP and settings screens |
| `src/lib/` | API client, canvas geometry, connector catalogue, expressions, conditions and other logic without React |
| `src/design/` | Typed style slots and shared UI primitives built on the theme |
| `theme/` | Panda design tokens, global styles and component recipes |
| `styled-system/` | Panda output, generated by `panda codegen` (do not edit) |
| `tests/` | Unit tests, run with Node's built-in test runner |
| `public/` | Favicon and brand assets |

TypeScript types for API responses come from [`packages/contracts`](../../packages/contracts).

## Conventions

- **Styling:** use theme tokens and recipes rather than ad hoc CSS. See [styling the UI](../../docs/styling.md).
- **Logic:** keep it in `src/lib` as plain TypeScript, so it can be unit tested without a browser.
- **Backend:** don't duplicate rules the Worker enforces. Show the errors it returns instead.
- **Unavailable features:** show an explicit unavailable state rather than placeholder data. See [UI implementation](../../docs/ui-implementation.md) for the current boundaries.
